# CineBar 本地片库设计规格

日期：2026-08-02  
状态：设计已确认，等待实施计划  
范围：macOS CineBar 本地片库管理

## 1. 目标

为 CineBar 增加一个与“电影、电视剧、我的片单”并列的“本地片库”分页，让用户管理自己拥有或已合法保存到本机、外置硬盘或已挂载 NAS 的影片文件。

本功能必须满足：

- 用户主动选择目录后才扫描，递归扫描子目录。
- 文件只在本机读取，不上传、不复制、不向第三方资源网站抓取下载链接。
- 元数据匹配失败不能阻止本地播放。
- 播放优先使用 IINA，其次 VLC，最后使用 macOS 系统播放器。
- 用户点击“刷新”后，新增影片必须进入片库，且不得生成重复条目。
- 文件移动、删除或外置存储未连接时保留记录，不静默删除。
- 片库中的“已看 / 未看”、片单收藏和最近打开时间可持久化。

## 2. 非目标

本版本不包含：

- 盗版资源聚合、磁力链接、迅雷链接或第三方下载入口。
- 自动爬取或下载远程影视文件。
- 将影片复制到 CineBar 专属目录。
- 在 CineBar 内嵌视频解码器或实现完整播放器。
- 跨 IINA、VLC 和系统播放器读取或同步播放进度。
- 以本地文件为依据自动覆盖 TMDB、OMDb 或用户评分。

## 3. 方案选择

### 采用：目录索引 + 外部播放器

CineBar 只保存用户授权目录中的文件索引和元数据，播放时把文件 URL 交给外部播放器。

优点：

- 不复制大文件，节省磁盘空间。
- 兼容 IINA/VLC 对 MKV、字幕和不同编码的处理能力。
- 本地播放不依赖网络。
- 目录权限和文件状态可以独立管理。

### 未采用的方案

1. **复制/导入到 CineBar 片库**：实现简单，但重复占用磁盘，外置盘和 NAS 场景不适合。
2. **内嵌 AVPlayer**：界面统一，但对 MKV、音轨、字幕和编码的兼容性不足，且会把播放器维护成本引入 CineBar。

## 4. 模块边界

### `LocalLibraryStore`

负责本地条目、目录授权、匹配状态、观看状态和收藏状态的加载、更新与保存。不负责扫描目录，也不负责启动播放器。

### `LocalLibraryScanner`

以后台任务递归扫描已授权目录，识别视频文件，生成或更新条目。扫描过程不得阻塞 SwiftUI 主线程。

初版支持以下扩展名：

`.mp4`、`.m4v`、`.mov`、`.mkv`、`.avi`、`.webm`、`.ts`、`.m2ts`

扫描结果以文件路径、文件大小、修改时间和文件资源标识作为稳定性依据；同一文件重复扫描不得产生重复条目。

### `MetadataMatchService`

复用 CineBar 现有的 TMDB 代理服务，根据文件名清洗结果和可解析的年份生成候选。候选必须展示片名、年份、海报、类型和评分，由用户确认后写入绑定关系。

网络不可用时只标记为“待匹配”，不得删除本地文件条目，也不得阻止播放。

### `ExternalPlayerLauncher`

按以下顺序尝试打开文件：

1. IINA
2. VLC
3. macOS 系统默认播放器

应用检测不到某个播放器，或启动失败时继续尝试下一个；全部失败时显示明确错误和文件路径，不执行未经用户确认的 shell 命令。

### `LocalLibraryView`

提供本地片库分页、目录管理、扫描、搜索、筛选、匹配确认、播放、已看标记、片单收藏和重新定位文件入口。

## 5. 数据模型

数据保存位置：

```text
~/Library/Application Support/CineBar/LocalLibrary.json
```

每个视频条目至少包含：

- 本地文件 URL 或相对书签引用
- 所属根目录标识
- 文件名、扩展名、文件大小、修改时间
- 文件状态：`available`、`missing`、`volumeUnavailable`
- 匹配状态：`unmatched`、`suggested`、`confirmed`
- 已确认的 TMDB 类型和 ID（可为空）
- 用户状态：已看/未看、收藏、最近打开时间

目录授权信息使用 macOS security-scoped bookmark 保存，不把原始访问令牌写入界面或日志。

海报、简介和评分保存为轻量元数据或 URL，不保存封面原图；匹配信息缺失时仍可显示本地文件名并播放。

## 6. 主要交互

### 添加目录

用户点击“添加文件夹”，通过 `NSOpenPanel` 选择目录并授权。允许添加多个目录；默认递归扫描子目录。重复添加同一目录时复用已有授权和索引。

### 扫描与刷新

界面提供“刷新”按钮。点击后重新扫描所有已授权目录，发现新增视频文件并加入片库，同时更新已删除、移动或外置存储未连接的文件状态。扫描必须使用文件路径、文件大小、修改时间和文件资源标识去重，不得生成重复条目；已有的匹配、收藏、已看状态和最近打开时间必须保留。

“扫描全部”与“刷新”使用同一套扫描逻辑；单个目录也可单独重新扫描。刷新只负责本地文件索引和状态同步，不自动重新拉取所有 TMDB 数据。待匹配条目继续显示“匹配影片”入口，由用户确认后再绑定元数据。

扫描期间显示进度和已发现数量，界面保持可操作。应用退出或扫描中断时，已完成的条目立即保存。

### 列表

每行显示海报（有匹配时）、片名/文件名、年份、类型、匹配状态、文件状态和已看状态。右侧提供播放、收藏和标记已看操作。支持搜索文件名和已匹配片名，支持“全部、未看、文件不可用、待匹配”筛选。

### 匹配确认

“待确认匹配”打开候选面板。用户可确认一个候选，也可跳过匹配。跳过后仍可播放，并可以稍后再次匹配。

### 文件失效与重新定位

文件被移动、删除或存储卷未连接时保留记录并显示原因。用户点击“重新定位文件”后选择新文件；系统以文件名、扩展名、文件大小和修改时间组成的轻量签名进行确认，必要时再读取 macOS 文件资源标识。确认相符后只更新路径，不丢失匹配、收藏和已看状态。

### 播放与观看状态

点击播放按 IINA → VLC → 系统播放器顺序执行。播放成功后更新最近打开时间；“已看/未看”由用户手动切换。初版不自动写入播放进度。

## 7. 权限、隐私和安全

- 只访问用户通过 macOS 文件选择器明确授权的目录。
- 不扫描整个磁盘，不读取未授权目录。
- 不上传本地路径、文件内容或影片文件。
- 外部播放器启动使用系统 URL/应用打开接口，不拼接未经校验的 shell 命令。
- 日志中不输出完整的个人目录路径，错误提示只在本地界面显示必要信息。
- 目录权限失效时重新请求授权，不绕过系统权限控制。

## 8. 错误处理

| 情况 | 行为 |
| --- | --- |
| TMDB 网络不可用 | 保留条目，显示“待匹配”，仍可播放 |
| 同名影片 | 显示候选，禁止静默绑定 |
| 文件被移动/删除 | 标记“文件不可用”，提供重新定位 |
| 外置硬盘/NAS 未连接 | 标记“存储卷未连接”，不删除记录 |
| IINA 未安装 | 尝试 VLC |
| IINA、VLC 均不可用 | 尝试系统默认播放器 |
| 所有播放器均失败 | 显示可复制的本地路径和错误原因 |
| 用户取消授权 | 停止当前扫描，保留已有片库记录 |
| 文件格式无法播放 | 保留条目，提示由播放器负责格式支持 |

## 9. 测试与验收

### 自动化测试

- 文件名、年份和扩展名解析。
- 重复扫描去重。
- 刷新后新增影片进入片库，已有条目不重复。
- 文件可用、缺失和存储卷不可用状态转换。
- 播放器检测和 IINA → VLC → 系统播放器回退顺序。
- security-scoped bookmark 保存和恢复。
- TMDB 候选排序、确认和跳过匹配。
- 已看、片单和最近打开时间持久化。

### 手动验收

1. 添加包含多层子目录的影片文件夹。
2. 扫描至少 50 个视频文件时界面仍可操作。
3. 在已授权目录中加入新影片，点击“刷新”，确认新影片进入片库且旧条目不重复。
4. 断开外置硬盘，确认记录保留且状态正确。
5. 重新连接硬盘，确认条目自动恢复可用。
6. 卸载 IINA，确认自动尝试 VLC。
7. IINA/VLC 均不存在时，确认系统播放器可用。
8. 关闭网络，确认已扫描影片仍可播放。
9. 移动或删除文件，确认显示重新定位入口。
10. 重启 CineBar，确认目录授权、片库和状态仍然存在。

## 10. 兼容性与发布

本功能以现有 CineBar 数据和更新机制为基础，新增 JSON 文件不存在时自动创建；旧版本用户首次进入“本地片库”时显示空状态，不影响电影、电视剧、我的片单和在线更新。

所有新字段必须有默认值，读取损坏或旧格式 JSON 时保留可恢复的备份并以空片库启动，不影响应用启动。

## 11. 验收结论

只有在目录授权、递归扫描、匹配确认、三层播放器回退、失效文件处理、状态持久化和断网播放全部通过后，才视为本功能完成。任何远程资源抓取或第三方下载链接均不属于本功能范围。
