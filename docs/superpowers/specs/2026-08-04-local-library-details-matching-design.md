# 本地片库详情与匹配优化设计

## 目标

让本地片库具备清晰的“电影 / 电视剧 / 其他视频”分栏；匹配后的电影和电视剧复用 CineBar 现有完整详情页；未匹配的其他视频显示本地文件详情；匹配界面支持关闭、模糊排序和最佳建议。

## 已确认的边界

- 电影和电视剧必须由用户确认匹配后，才进入对应分类并使用外部资料。
- 其他视频没有可靠的外部媒体 ID 时，不伪造评分、演员、剧照或预告。
- 其他视频仍保留在本地片库，可查看文件详情、播放、重新定位和发起手动匹配。
- 外部详情数据继续使用现有 TMDB、OMDb、社区评分和 TVMaze 服务；不新增盗版资源来源。

## 方案与架构

采用复用现有详情页的桥接方案，不复制电影/电视剧详情逻辑。

1. `LocalLibraryView` 使用独立的内容分类分栏和状态筛选。分栏只负责过滤本地条目，不改变扫描、持久化或播放行为。
2. `LocalLibraryMetadata` 增加到现有 `Movie` / `TVShow` 的桥接初始化器。用户点击已匹配条目时，`MovieStore` 选择桥接对象，`ContentView` 路由到现有 `MovieDetailView` 或 `TVDetailView`。保留 `isShowingLocalLibrary`，因此详情页返回后回到本地片库及原分类。
3. 未匹配或“其他视频”点击时打开 `LocalLibraryFileDetailView`，只展示本地字段与可用操作。确认匹配后关闭本地文件详情，并转到完整外部详情页。
4. 匹配服务对 TMDB 搜索结果进行本地重排：标准化标题、词元 Jaccard 重叠、包含关系、编辑距离相似度和年份加分。排序后的第一项是最佳建议，UI 明确标记但仍要求手动确认。
5. 其他视频也可以在匹配页选择电影或电视剧并输入片名；手动搜索不再被 `.other` 分类拦截。

## 交互细节

- 本地片库顶部显示三个分栏：电影、电视剧、其他视频；另保留全部作为回看入口。
- 状态筛选独立为菜单：全部、未看、待匹配、文件不可用。
- 本地电影/电视剧行显示海报、标题、评分、匹配状态，以及“查看详情”“播放”“片单”“已看”等操作。
- 匹配页标题栏左侧有关闭按钮；关闭、跳过和系统关闭行为一致，不修改文件或元数据。
- 搜索结果第一项显示“最佳建议”徽标和相似度；每项仍有“确认匹配”按钮。
- 搜索失败或没有结果时保留当前条目，不清除原有资料；网络错误显示可本地化的错误提示。

## 数据流与错误处理

- 扫描和刷新继续由 `LocalLibraryScanner` / `LocalLibraryRefreshMerger` 管理，分类和已确认元数据必须保留。
- 详情桥接只读 `LocalLibraryEntry.metadata`；缺少 metadata、ID 小于等于 0 或类别为 other 时不进入外部详情页。
- 外部详情加载失败时沿用现有详情页的缓存/空状态，不影响本地文件播放。
- 本地文件详情中的播放仍优先 IINA，再 VLC，最后系统播放器；文件不可用时只允许重新定位。
- 任何匹配确认都走 `LocalLibraryStore.confirmMatch`，持久化成功后才改变分类。

## 测试策略

- Swift 回归测试覆盖：分类筛选只返回对应条目；其他视频允许手动电影/电视剧搜索；标题轻微拼写差异时最佳候选排序正确；metadata 可桥接为 Movie/TVShow；确认匹配后类别和状态变化正确。
- UI 源码检查覆盖：三个可见分栏、关闭按钮、最佳建议徽标和“查看详情”入口存在。
- 保留并运行现有扫描、刷新、播放器、详情、评分和本地化回归测试。

## 非目标

- 不复制或重写现有 `MovieDetailView` / `TVDetailView`。
- 不把个人视频自动当作电影或电视剧。
- 不新增账号登录、社区账号或第三方盗版下载聚合。
