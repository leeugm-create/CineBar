# CineBar 官网与安全应用内更新设计

日期：2026-07-30
状态：等待最终规格确认
目标版本：CineBar 0.8.2 后续测试版（Build 17 或更高）

## 1. 目标

为 CineBar 建立一个可长期维护的简洁官网，并为官网发布包与 macOS
客户端建立同一条安全更新链路。

本轮交付需要满足：

- `https://cinebar.cc` 成为 CineBar 官方产品主页；
- 页面自动跟随访客的 macOS、iOS 或浏览器深色/浅色外观；
- 页面结构简洁、易读，移动端和桌面端均可正常浏览；
- 主下载入口指向 GitHub Releases；
- CineBar 客户端能够在应用内发现、下载、验证并安装新版本；
- 更新安装前由用户明确确认，完成后重新启动 CineBar；
- 保留 Build 16 已有的电影、电视剧、分享、主演信息、即将上映日期、
  自定义域名和网络降级功能；
- 不破坏现有 `/m/<ID>`、`/t/<ID>`、`/health` 和更新检查路径；
- 不把测试版描述为正式稳定版。

## 2. 非目标

第一阶段不包含：

- Mac App Store 上架；
- Apple Developer ID 签名或 Apple 公证；
- 无提示、不可撤销的后台静默安装；
- 用户账号、会员、广告或订阅系统；
- 在线影片播放或下载；
- 将 API、社区评分或分享服务合并到同一个进程；
- 用官网替代 GitHub 作为安装包文件仓库。

## 3. 信息架构

### 3.1 域名职责

- `cinebar.cc`
  - 产品官网；
  - 安装说明；
  - 隐私与数据来源说明；
  - 支持开发者入口；
  - Sparkle 更新订阅 `appcast.xml`。
- `share.cinebar.cc`
  - `/m/<TMDB ID>` 电影分享页；
  - `/t/<TMDB ID>` 电视剧分享页；
  - 兼容现有客户端的 `/updates/latest.json`。
- `api.cinebar.cc`
  - TMDB、OMDb 等影片与评分数据代理。
- `community.cinebar.cc`
  - CineBar 匿名社区评分服务。

三个服务子域名保持独立。官网故障不得影响客户端影片数据或社区评分。

### 3.2 官网页面结构

第一版采用单页产品官网，导航锚点保持精简：

1. 首页；
2. 功能；
3. 安装；
4. 隐私；
5. 支持。

页面内容顺序：

1. 顶部导航；
2. 首屏品牌与主要下载按钮；
3. 产品界面展示；
4. 核心功能；
5. 当前测试版本与更新方式；
6. 安装步骤；
7. 免费承诺、隐私和数据来源；
8. 支持 CineBar；
9. 页脚、GitHub Releases 和服务状态入口。

## 4. 视觉设计

### 4.1 设计原则

- 优先保证文本对比度、字号和阅读顺序；
- 不堆叠大面积透明玻璃，避免纯黑背景下文字失去可读性；
- 每屏只保留一个主要动作；
- 使用 CineBar 现有深蓝、橙色作为品牌色；
- 动画只用于状态反馈，尊重 `prefers-reduced-motion`；
- 不使用伪造评分、用户数、下载量或媒体评价。

### 4.2 深色与浅色外观

默认通过 `prefers-color-scheme` 跟随系统，不要求用户手动设置。

- 浅色模式：暖白背景、深蓝正文、低饱和灰色卡片和橙色强调色；
- 深色模式：深蓝背景、接近白色正文、提高边框与次要文字对比度；
- Logo 图标提供浅色与深色适配版本；
- 浏览器主题色、favicon 和 Apple Touch Icon 与当前外观协调；
- 无 JavaScript 时仍能正确跟随系统外观。

第一版不增加网站内的手动主题开关，避免重复系统设置并降低界面复杂度。

### 4.3 响应式布局

- 大屏首屏为品牌文案与产品界面双栏；
- 窄屏自动变为单栏；
- 主按钮最小可点击高度 44 点；
- 正文最大行宽约 68 个中文字符；
- 关键内容不依赖鼠标悬停才能阅读。

## 5. 官网内容

### 5.1 首屏

- 品牌：CineBar；
- 标语：今晚看什么？

主下载按钮打开：

`https://github.com/leeugm-create/CineBar/releases`

不写死某个 ZIP 资源地址，以免官网长期指向旧包。

### 5.2 功能

官网只突出可验证的现有能力：

- 本周热门、每日推荐、即将上映和今日播出；
- TMDB、IMDb、烂番茄、Metacritic 与 CineBar 评分；

- 国家、年代和类型筛选；

- 合法观看平台入口；
- 中文简体、中文繁体、英语、日语和韩语；
- 品牌短链接分享。

### 5.3 安装说明

必须明确：

- 当前测试包尚未经过 Apple Developer ID 签名和公证；
- 首次打开可能出现来源提示；
- 用户应只从 CineBar GitHub Releases 或官网入口下载；
- 提供解压、移动到“应用程序”、首次右键打开的步骤；
- 不要求用户部署 Cloudflare、申请 TMDB/OMDb 密钥或安装 Node.js。

### 5.4 隐私与数据来源

官网说明：

- CineBar 不出售个人数据；
- 不要求注册账号；
- 我的片单和偏好默认保存在本机；
- 社区评分使用匿名设备标识并受“一部作品一次评分”限制；
- 影片资料和评分来自各自标明的数据提供方；
- CineBar 不提供盗版片源或非法下载。

### 5.5 支持

- 承诺软件免费、无广告、无订阅；
- 提供自愿的一次性 PayPal 支持入口；
- 支持按钮必须明确标注为自愿支持，不暗示购买软件、会员或服务；
- 支持失败不得影响下载和使用。

## 6. 更新系统

### 6.1 现状

Build 16 已能读取：

`https://share.cinebar.cc/updates/latest.json`

并比较 `CFBundleVersion`，但当前只展示版本信息；清单中的
`download_url` 为空，也没有安装器，因此它不是完整的应用内更新。

### 6.2 目标架构

后续构建集成 Sparkle 2：

- 更新订阅：`https://cinebar.cc/appcast.xml`；
- 更新包：GitHub Release 中的 Universal ZIP；
- 每个更新包使用 Sparkle EdDSA 签名；
- 公钥固定内置在 CineBar `Info.plist`；
- 私钥只保存在开发者本机钥匙串和离线备份中；
- `CFBundleVersion` 必须严格递增；
- 更新界面展示版本号、发布日期、更新说明和文件大小；
- 用户点击“安装并重新启动”后才执行替换；
- 下载或签名验证失败时保持当前版本可用；
- 禁止在验证失败后退回到不验证的普通下载。

Sparkle 的标准安装流程负责下载、签名校验、原子替换和重新启动。
不自行编写 shell 脚本替换 `/Applications/CineBar.app`。

### 6.3 无 Apple 开发者账号阶段

- 首次安装仍可能触发 macOS Gatekeeper 提示；
- 后续更新依赖 HTTPS 与 Sparkle EdDSA 双重基础保护；
- 官网和应用不得声称安装包已由 Apple 公证；
- 自动检查可以默认开启；
- 安装必须由用户确认；
- 不默认启用无提示静默安装。

取得 Apple Developer ID 后，增加：

- Developer ID Application 签名；
- Hardened Runtime；
- Apple 公证和 stapling；
- 在验证完整更新路径后，再向用户提供可选后台自动安装。

### 6.4 兼容现有 Build 16

Build 16 不包含 Sparkle，无法通过网页远程获得新的安装能力。

过渡方式：

1. 更新 `/updates/latest.json`，让 Build 16 显示新版本；
2. `download_url` 指向 GitHub Releases；
3. Build 16 用户通过浏览器手动安装第一个带 Sparkle 的版本；
4. 从该版本开始，后续版本使用应用内安装。

这是一次性迁移，不能承诺 Build 16 本身直接变成全自动更新客户端。

## 7. 发布流程

每次发布按固定顺序执行：

1. 更新版本号、Build 号和更新说明；
2. 构建 Apple 芯片与 Intel 的 Universal 应用；
3. 运行回归测试；
4. 打包 ZIP；
5. 使用 Sparkle EdDSA 私钥签名；
6. 创建 GitHub Pre-release 或 Release 并上传 ZIP；
7. 生成或更新 `appcast.xml`；
8. 更新 `/updates/latest.json` 兼容旧客户端；
9. 更新官网当前版本信息；
10. 部署官网和更新订阅；
11. 使用旧版 CineBar 完成一次真实升级测试；
12. 验证失败时停止发布，不修改线上稳定清单。

测试版继续使用 GitHub Pre-release，只有经过多台 Mac 和多网络验证后才取消
Pre-release 标记。

## 8. 安全与故障处理

- 官网和更新源只使用 HTTPS；
- 更新包必须通过 EdDSA 校验；
- 私钥不上传 GitHub、Cloudflare 或项目仓库；
- 页面使用严格的安全响应头；
- 外部链接使用安全的 `rel` 属性；
- 官网资源失败时仍显示文本和下载入口；
- GitHub 暂时不可用时显示清晰提示，不改指向未知镜像；
- `appcast.xml` 无效时，客户端保持现有版本并提示检查失败；
- 不允许更新失败导致 CineBar.app 被删除或留下半安装状态。

## 9. 验收标准

### 官网

- `cinebar.cc` 在深色和浅色系统外观下均清晰可读；
- Safari、Chrome 桌面端和移动端布局无横向溢出；
- 下载按钮进入正确的 GitHub Releases；
- 安装、隐私、数据来源和测试版提示可见；
- `share.cinebar.cc/m/<ID>` 与 `/t/<ID>` 行为保持不变；
- API、社区评分和健康检查不受官网部署影响。

### 更新

- Build 号更高时显示更新；
- Build 号相同或更低时不提示；
- 修改 ZIP 任意字节后签名校验必须失败；
- 用户取消更新时当前版本继续运行；
- 更新成功后自动重新启动到新 Build；
- 网络中断后不会破坏已安装版本；
- 旧 Build 16 仍可通过 `latest.json` 进入 GitHub Releases 完成一次性迁移。

## 10. 实施顺序

1. 建立官网页面与深浅色设计；
2. 保留并回归验证现有 Worker 路由；
3. 部署官网第一版；
4. 为下一 Build 集成 Sparkle；
5. 建立 EdDSA 密钥、appcast 和发布脚本；
6. 制作迁移测试包；
7. 从 Build 16 执行一次手动迁移；
8. 从带 Sparkle 的旧 Build 执行一次应用内更新；
9. 验证通过后发布 GitHub Pre-release。
