# CineBar 统一分享与影片信息增强设计

## 背景与已验证事实

CineBar 目前向 `NSSharingServicePicker` 同时传入一段 `NSString` 文案和一个
`NSURL`。在用户当前的 macOS 环境中，系统分享面板因此没有列出微信。

同一台 Mac、同一版本微信中，Safari 分享普通网页时会列出“发送到微信”。这说明
微信扩展本身已安装并启用，差异来自分享项目的表示方式，而不是微信安装状态。

本机检查还确认，X 是安装在 `~/Applications/Chrome Apps.localized` 下的网页
应用，不包含 macOS 原生分享扩展。因此 CineBar 和 macOS 都不能强制让 X 出现在
系统分享面板。

## 目标

1. 影片和电视剧详情页只保留一个统一、直接的系统分享入口。
2. 分享行为仿照 Safari：向系统只提交一个远程网页 URL，而不是“文案和 URL”
   两个独立项目。
3. 分享预览和分享网页清楚显示 CineBar 品牌、影片资料和主要演员。
4. 分享网页提供明确的 CineBar 版本下载入口。
5. “即将上映”电影列表直接显示具体上映日期或“日期待定”。
6. 本轮功能改动不冒充尚未完成的大陆网络修复。

## 非目标

- 本轮不购买或接入 `cinebar.cc`。
- 本轮不修复 `workers.dev` 在部分大陆网络中的 DNS/TLS 可达性。
- 不为 X、微博、微信或 Instagram 制作单独按钮。
- 不承诺未提供原生 macOS 分享扩展的平台会出现在系统分享面板。
- 不增加相关新闻。
- 不发布正式版或 GitHub Release。

## 统一分享交互

电影和电视剧详情页继续显示现有分享图标，但图标不再打开 CineBar 的分平台菜单。
用户单击后立即打开 macOS 系统分享面板。

提交给 `NSSharingServicePicker` 的项目数组必须只含影片的品牌分享 URL：

```text
[payload.url as NSURL]
```

不得再同时提交独立的长文案。这样系统会把内容视为一个网页项目，并自行匹配可处理
网页链接的扩展。系统分享面板中的“拷贝”成为未提供原生扩展的平台的通用后备；
用户可以把链接粘贴到 X、网页聊天工具或其他应用。

删除详情页分享菜单中的以下入口：

- 复制分享文案；
- 分享到 X；
- 分享到微博；
- 面向具体平台的说明文字。

分享按钮帮助文字统一为“分享”。分享是否成功仍由 macOS 和目标扩展负责，CineBar
不伪造目标平台，也不绕过系统权限。

## 系统预览与分享页面

分享面板顶部预览和网页元数据使用统一标题：

```text
《影片名称》— CineBar
```

电视剧使用相同格式。分享页继续使用永久短路径：

- 电影：`/m/<TMDB ID>`
- 电视剧：`/t/<TMDB ID>`

Worker 获取详情时一并获取 credits。页面展示按 TMDB 返回顺序排列的前 6 位演员，
每位显示演员姓名；有角色名时显示“饰 角色名”。演员信息同时用于生成简短的
Open Graph 描述，但不得让描述超过适合社交预览的长度。

分享页面包含：

- CineBar Logo 与名称；
- 海报；
- 片名；
- 年份；
- TMDB 评分；
- 简介；
- 主要演员；
- “查看 CineBar 版本与下载”按钮。

下载按钮固定指向：

```text
https://github.com/leeugm-create/CineBar/releases
```

按钮文案必须说明它打开的是版本列表，不能暗示一定存在稳定正式版，也不能自动下载
未知文件。

所有来自 TMDB 的文本必须经过 HTML 转义。演员请求失败时仍显示其余影片资料，只
隐藏演员区域；影片详情请求整体失败时继续显示现有品牌兜底页。下载地址仍只接受
HTTPS URL。

## 即将上映日期

`MovieRow` 新增可选的上映日期标签，仅在“即将上映”分页传入并显示。日期来自列表
结果的 `release_date`，不为每一行额外发送网络请求。

- 有有效日期：显示带日历图标的本地化日期。
- 只有不完整或无效日期：显示“上映日期待定”。
- 其他电影分页不显示该标签。
- 返回详情页后不得改变列表顺序或日期显示。

中文简体和繁体使用 `yyyy年M月d日`，英文使用本地化月日年格式，日文和韩文使用
各自系统区域格式。原始日期解析固定使用 `en_US_POSIX` 和公历，显示使用用户当前
CineBar 语言对应的区域。

## 组件边界

### macOS 客户端

- `SharePayload` 继续负责片名、媒体类型和品牌 URL。
- 新增一个可测试的分享项目生成接口，只返回一个 `NSURL`。
- `SystemSharePresenter` 只负责锚定并显示系统分享面板。
- `MediaShareMenu` 改为单一按钮，或以等价的 `MediaShareButton` 替代。
- `MovieRow` 接收可选上映日期展示值，不读取全局分页状态。

### Cloudflare 分享 Worker

- `loadMetadata` 返回影片资料和最多 6 位演员。
- `sharePage` 负责品牌页面、Open Graph 元数据、演员区和版本入口。
- Worker 环境变量中的下载地址设置为 GitHub Releases 页面。
- 现有 `/m/`、`/t/` 路由保持不变，旧分享链接继续有效。

## 错误处理

- 无品牌分享 URL：分享按钮禁用，并显示现有服务未配置提示。
- 分享锚点窗口不存在：不崩溃，直接结束本次操作。
- 演员为空或 credits 请求失败：隐藏演员区域，不显示虚假占位演员。
- 海报无效：继续使用 CineBar Logo。
- GitHub Releases 地址无效或不是 HTTPS：隐藏下载按钮。
- 微信仍未出现：先验证分享项目数组确实只有 URL，再检查微信扩展；不得重新加入
  平台专用按钮来掩盖根因。

## 测试与验收

### 自动测试

1. Swift 回归测试验证分享项目数组恰好包含一个 URL，且不含第二个字符串项目。
2. Swift 回归测试验证电影与电视剧品牌短路径保持不变。
3. Swift 回归测试验证即将上映日期的有效、缺失和无效输入。
4. Worker 测试验证前 6 位演员、角色名和 HTML 转义。
5. Worker 测试验证 credits 失败不会破坏影片详情页。
6. Worker 测试验证 GitHub Releases HTTPS 下载入口出现。
7. Worker 测试验证无效下载地址仍被隐藏。
8. 本地化完整性测试覆盖新增文案。

### 手工验收

1. 在用户当前 Mac 上打开电影详情，单击分享图标。
2. 分享面板立即出现，不先显示 CineBar 平台菜单。
3. 分享面板预览只显示一个 CineBar 网页项目。
4. “发送到微信”出现并可打开微信分享扩展。
5. “拷贝”得到品牌分享 URL，能粘贴到 X 网页应用。
6. 电影和电视剧分享网页显示对应资料、主要演员及 GitHub Releases 按钮。
7. “即将上映”列表每一项显示具体日期或“上映日期待定”。

## 发布边界

本轮可以生成仅供本机验证的功能预览包，但不能标注为大陆网络修复版。现有
`workers.dev` 分享地址在部分大陆网络仍可能失败。正式分发包必须等
`cinebar.cc` 注册、三个自定义服务域名启用并通过运营商网络测试后再制作。
