# CineBar 手机官网首页：内嵌在线播放设计规格

状态：待用户评审
日期：2026-08-11
范围：`https://cinebar.cc/` 在手机浏览器中的首页

## 决策

采用 A 方案：

`搜索结果 → 点击影片 → 首页内展开播放器 → 用户点击播放`

本次只改变手机浏览器首页。桌面端首页、macOS App、分享页和其他官网路由不改变。

## 目标

- 手机用户打开首页后，第一眼看到 CineBar 品牌和搜索入口。
- 搜索电影、电视剧和动漫后，可以在首页内查看可播放内容。
- 不因为首页展示播放器而在首次打开时下载视频或占用大量内存。
- 播放失败时给出明确状态，不展示看似可用但实际为空的播放器。

## 非目标

- 不在本次工作中改桌面端布局。
- 不把分享页改成播放器，也不把用户强制跳转到分享页。
- 不抓取或代理未授权、受防盗链或 DRM 保护的视频资源。
- 不承诺所有搜索结果都有在线播放源；TMDB 搜索结果本身只代表影片资料，不代表存在可播放地址。

## 手机首页布局

### 默认状态

1. 顶部栏只保留 CineBar Logo/名称和搜索图标。
2. 隐藏桌面导航、语言切换、主题切换和下载/支持等桌面优先操作；这些能力不删除，只不占用手机首屏。
3. 首页首屏以“搜索电影、电视剧与动漫”为主提示，避免把 GIF、安装说明和大段产品介绍放在搜索入口之前。
4. 首次渲染不创建 `<video>`、`iframe` 或其他媒体连接。

### 搜索状态

1. 点击搜索图标后，图标区域展开为全宽搜索输入框并自动聚焦。
2. 输入至少两个字符后按现有 `/api/search` 进行防抖搜索。
3. 搜索结果使用紧凑卡片：海报、片名、年份、内容类型、评分、播放状态。
4. 支持清除输入、关闭搜索和保留现有搜索历史。
5. 结果排序继续由现有搜索 API 决定；本次不伪造“可播放”状态。

### 播放状态

1. 点击结果卡片后，在搜索结果上方插入唯一一个 16:9 播放器容器。
2. 先显示海报、片名和播放按钮；用户点击播放后才建立媒体连接。
3. 不依赖带声音自动播放。手机浏览器可能阻止自动播放，用户点击播放是正常流程。
4. 播放器提供关闭/收起操作；关闭后释放媒体元素并恢复结果列表。
5. 点击另一部影片时，先暂停并卸载旧播放器，再加载新影片，任何时刻只允许一个活跃播放器。
6. 播放器下方显示片名、类型、年份和来源标签；不把无法验证的来源写成“可观看”。
7. 没有合法、可嵌入且兼容手机浏览器的播放源时，显示“暂无可在线播放源”，保留资料结果，不显示空白播放器。
8. 播放错误时显示可理解的错误提示和重试按钮；不自动跳离首页。

## 数据与播放源前置条件

当前网站 `/api/search` 只返回 TMDB 元数据（`type/id/title/year/poster/rating`），不返回播放地址。因此前端改造不能单独解决“能在线看”。实现前必须选定一个受支持的播放源契约，例如：

```ts
type WatchSource = {
  kind: "html5" | "hls" | "embed";
  url: string;
  label: string;
  region?: string;
};

type SearchHit = {
  // existing metadata...
  watch?: WatchSource[];
};
```

播放源 API 必须满足：

- 来源合法且可持续使用；
- 明确允许网页播放或嵌入；
- 支持 HTTPS；
- 对 `video`/HLS 或嵌入页面提供正确的跨域和响应头；
- 不把第三方盗版站、迅雷/磁力链接或需要绕过防盗链的地址接入官网播放器。

如果暂时没有满足条件的源，第一阶段应先完成“搜索结果 + 播放状态占位 + 明确暂无播放源”，而不是把任意网页 URL 塞进播放器。

## 性能与稳定性约束

- 视频媒体只在用户点击播放后请求，海报和结果图片懒加载。
- 关闭或切换影片时调用暂停、移除 `src`/播放器节点并释放引用。
- 搜索请求继续使用 AbortController，旧查询不能覆盖新查询。
- 移动端播放器使用稳定宽高比，避免打开/关闭时页面跳动。
- 不在首屏加载 GIF 产品演示；产品演示下移或移动端隐藏，优先保障搜索和播放。
- 不改变桌面端现有 CSS 和 DOM 行为；新增样式应限定在移动断点或移动首页容器内。

## 无障碍与交互细节

- 搜索图标、关闭、清除、播放和重试按钮均有可读的 `aria-label`。
- 触控目标不小于 44×44 CSS 像素。
- 搜索结果卡片支持键盘焦点和明显的焦点样式。
- `prefers-reduced-motion` 下不使用展开动画或将动画降为淡入。
- 播放器错误、无源和加载状态使用文字，不只依赖颜色或图标。

## 验收标准

### 手机浏览器

- [ ] 默认首页只突出 Logo 和搜索入口；没有桌面导航挤压首屏。
- [ ] 点击搜索图标会展开并聚焦输入框。
- [ ] 搜索结果显示海报、片名、类型、年份、评分和播放状态。
- [ ] 点击结果不会跳转 URL，而是在当前首页展开播放器。
- [ ] 首次打开和仅搜索时不建立视频网络请求。
- [ ] 用户点击播放后才建立媒体连接。
- [ ] 同时最多一个播放器；切换和关闭能停止旧播放。
- [ ] 无播放源和播放失败均有清晰状态。
- [ ] 手机窄屏、横屏和系统深色模式下不溢出、不遮挡搜索和关闭控件。

### 回归

- [ ] 桌面端首页视觉和导航保持现状。
- [ ] `/share` 相关页面、Appcast、下载入口和支持页保持现状。
- [ ] 现有网站测试、构建和 lint 通过。
- [ ] 若新增播放 API，必须有跨域、错误响应和无源结果测试。

## 尚待实现前确认的技术事项

1. 选择并接入合法、可嵌入的播放源；现有 TMDB 搜索接口不能直接提供它。
2. 确定 `html5`/HLS/嵌入三种源中本版实际支持的最小集合。
3. 确认无源时只展示资料，不提供跳转播放链接，以符合本次“不跳转”的要求。
